As players take actions on their HUDs (playing distance cards, applying hazards, or executing safety moves), the game table updates physical car positions along a straight track, changes player-facing display screens, and renders text notifications in real time.

Communication Protocol & Data SchemaTo optimize execution speed and prevent LSL string allocation overhead, all communication from the HUD to the table bypasses heavy JSON object parsing in favor of a lightweight Pipe-Delimited (|) Raw Payload parsed via native LSL string splitting (llParseString2List).  2.1 Payload FormatPlaintext[EVENT_TYPE]|[PLAYER_NUM]|[TARGET_NUM]|[CARD_TYPE]|[CARD_VALUE]|[TOTAL_MILEAGE]

  ParameterTypeRange / Options  Description

  CARD_TYPEStringe.g., DISTANCE, FLAT_TIRE, SPARE_TIRE, GO, STOP, LIMIT, END_LIMITKey map for texture loading on target screens.  CARD_VALUEInteger0, 25, 50, 75, 100, 200Face value of the played card.

  3. Physical Track Geometry & Linkset Kinematics
  
  All car prims are linked directly to the Table Main Frame (Root Prim). The movement engine operates strictly within local linkset space (PRIM_POS_LOCAL and PRIM_ROT_LOCAL). This creates 100% orientation immunity—the table can be rezzed, rotated, or placed on a steep incline/angle in 3D space without requiring any world-space coordinate translations or rotation checks.  
  
  3.1 Verified Physical Track Constants
  Derived directly from in-world linkset inspection metrics:  
  
  ConstantValueDescription
  TRACK_START_Y -3.38593 Local Y coordinate representing 0 miles (Start Line).  
  TRACK_END_Y 3.46848 Local Y coordinate representing 1000 miles (Finish Line).  
  TOTAL_TRACK_METERS 6.85441 Total physical distance of the track in meters ($3.46848 - (-3.38593)$).  
  METERS_PER_MILE 0.00685441 Movement multiplier per unit of mileage ($6.85441 / 1000$).  
  CAR_LOCAL_Z 0.48999 Fixed vertical offset relative to table bed.  
  CAR_LOCAL_ROT <0.0, 0.0, -1.0, 0.0> Fixed local orientation quaternion ($180^\circ$ Euler on Z-axis).    
  
  3.2 Lane Alignment Matrix (Local X)
  Car 1 (car1): +0.44653  
  Car 2 (car2): +0.14680  
  Car 3 (car3): -0.14484  
  Car 4 (car4): -0.45563  
  
  3.3 Movement Equation
  
  For any player seat $P \in \{1, 2, 3, 4\}$ and absolute current mileage $m \in [0, 1000]$:  $$\vec{Pos}_{\text{Local}} = \left\langle \text{Lane\_X}_P,\, \left(-3.38593 + (m \times 0.00685441)\right),\, 0.48999 \right\rangle$$  
  
  3.4 Display Screens & Texture Swapping
  
  Each of the 4 player lanes features an individual display screen prim facing spectators. Preloaded texture UUIDs representing card actions (e.g., GO!, Flat Tire!, Spare Tire!, Winner, Game Over) swap instantly on designated prim faces using llSetLinkTexture upon event payload receipt.

## 3.6 Display Screen Architecture & Texture Specifications

### 3.6.1 Linkset Discovery & Seat Mapping
To guarantee stability against link-order changes when editing the table linkset, the display screens are consolidated into a single child prim named **`screens`**. The master LSL script dynamically resolves the link index of `screens` during `state_entry` and `changed(CHANGED_LINK)` events rather than relying on hardcoded link numbers.

Player seats (1 through 4) map directly to specific primitive face indices on the `screens` object:

| Player Seat / Sitter | Target Prim Name | Prim Face Index | Operational Role |
| :--- | :--- | :--- | :--- |
| **Player 1** (Sitter 0) | `screens` | `Face 0` | Display screen for Lane 1 |
| **Player 2** (Sitter 1) | `screens` | `Face 1` | Display screen for Lane 2 |
| **Player 3** (Sitter 2) | `screens` | `Face 2` | Display screen for Lane 3 |
| **Player 4** (Sitter 3) | `screens` | `Face 3` | Display screen for Lane 4 |

### 3.6.2 Dynamic Link Lookup Engine (LSL)
```lsl
integer gScreensLinkNum = 0; // Dynamic link index for the "screens" prim

// Scans the linkset for the "screens" child prim
findScreensLink()
{
    integer numberOfPrims = llGetNumberOfPrims();
    integer i;
    gScreensLinkNum = 0; // Reset
    
    for (i = 2; i <= numberOfPrims; ++i)
    {
        if (llGetLinkName(i) == "screens")
        {
            gScreensLinkNum = i;
            return;
        }
    }
}

// Set texture on a specific player screen face (Seat 1-4 -> Face 0-3)
setPlayerScreenTexture(integer playerSeat, string textureUUID)
{
    if (gScreensLinkNum > 0)
    {
        integer faceIndex = playerSeat - 1; // Maps Seat 1..4 to Face 0..3
        llSetLinkTexture(gScreensLinkNum, textureUUID, faceIndex);
    }
}  
  
  4. Production LSL Implementation
  
  The following LSL functions handle link indexing and instant, orientation-agnostic positioning updates. Passing absolute total mileage on every payload guarantees automatic state self-correction if a packet drops.  
  
  Code snippet// --- PHYSICAL TRACK GEOMETRY CONSTANTS ---
float TRACK_START_Y    = -3.38593;
float METERS_PER_MILE  = 0.00685441;
float CAR_LOCAL_Z      = 0.48999;
rotation CAR_LOCAL_ROT = <0.0, 0.0, -1.0, 0.0>; // Quaternion for Euler <0, 0, -180>

// Fixed Lane X Positions for Cars 1-4
list CAR_LANE_X = [0.44653, 0.14680, -0.14484, -0.45563];

// Link numbers mapped dynamically during state_entry or changed() events
list gCarLinkNums = [0, 0, 0, 0]; // Index map for [Car 1, Car 2, Car 3, Car 4]

// Index linked car prims by name
indexCarLinks()
{
    integer numberOfPrims = llGetNumberOfPrims();
    integer i;
    gCarLinkNums = [0, 0, 0, 0];
    
    for (i = 2; i <= numberOfPrims; ++i)
    {
        string pName = llGetLinkName(i);
        if (pName == "car1")      gCarLinkNums = llListReplaceList(gCarLinkNums, [i], 0, 0);
        else if (pName == "car2") gCarLinkNums = llListReplaceList(gCarLinkNums, [i], 1, 1);
        else if (pName == "car3") gCarLinkNums = llListReplaceList(gCarLinkNums, [i], 2, 2);
        else if (pName == "car4") gCarLinkNums = llListReplaceList(gCarLinkNums, [i], 3, 3);
    }
}

// Production Movement Execution Function
updateCarPosition(integer playerSeat, integer totalMiles)
{
    // 1. Safety clamp (0 to 1000 miles)
    if (totalMiles < 0) totalMiles = 0;
    if (totalMiles > 1000) totalMiles = 1000;

    // 2. Map seat (1-4) to 0-indexed list offset
    integer seatIdx = playerSeat - 1;
    integer carLink = llList2Integer(gCarLinkNums, seatIdx);
    
    if (carLink > 0)
    {
        // 3. Compute target local Y coordinate
        float laneX   = llList2Float(CAR_LANE_X, seatIdx);
        float targetY = TRACK_START_Y + ((float)totalMiles * METERS_PER_MILE);
        
        vector targetLocalPos = <laneX, targetY, CAR_LOCAL_Z>;

        // 4. Update position & enforce locked 180-degree local orientation
        llSetLinkPrimitiveParamsFast(carLink, [
            PRIM_POS_LOCAL, targetLocalPos,
            PRIM_ROT_LOCAL, CAR_LOCAL_ROT
        ]);
    }
}
  5. Turn Pacing & System Synchronizations
  
  5.1 Client-Side AI Pacing Pipeline (JavaScript)To give spectators time to digest computer-player moves and prevent LSL event queue saturation (maximum 64 events), the web client enforces artificial turn delays for bot actions:  
  
  PhaseDurationDescription
  
  Turn Start 1.0s Active turn indicator updates; text displays "THINKING...".  
  Card Play 2.0s Screen texture updates to played card image; SFX triggers.  
  Car Movement 1.5s Car glides forward along local +Y-axis on track.  
  Turn Buffer 0.5s Pause before passing execution to the next turn loop.    
  
  6. End-of-Game & Table Reset Workflow
  
  1.Receive Victory Payload:Event: GAME_OVER.Web HUD transmits GAME_OVER|winner_id to the table's HTTP-In endpoint. Table locks incoming game interactions.
  
  2.Execute Victory Sequence:Duration: ~5.0 seconds.Table sets winning seat screen to WINNER, remaining screens to GAME_OVER. Furware header flashes win announcement.
  
  3.Reset Table Geometry & Textures:All 4 cars return to local $Y_{\text{START}}$ coordinates (-3.38593). Display screens revert to Attract Mode graphics. Furware clears player names and sets prompt to "INSERT COIN / CLICK HUD TO START".
  
  4.HTTP Handshake Release:Table sends pending HTTP 200 response (TABLE_RESET_COMPLETE) back to the waiting web client. Web HUD unlocks UI and permits new game initialization.  
  
  7. Attract Mode (Idle State)
  
  When no game is active:  Slideshow Loop: A timer loop continuously cycles promotional and instruction textures across the 4 display screens.  Track Animation: Cars periodically execute subtle back-and-forth movement animations along local $+Y$ to draw spectator attention.  Interrupt Handshake: Any incoming GAME_START HTTP POST immediately terminates the timer loop and initializes player seat mappings.
